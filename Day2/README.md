# Day 2: Enhanced LLM Agent

Расширенная версия Day1 с дополнительными возможностями управления ответом LLM.

## Архитектура

Приложение реализовано на чистой HTTP-библиотеке Go (`net/http`) без использования сторонних SDK для LLM-провайдеров. Это обеспечивает:
- Полный контроль над формированием запросов и обработкой ответов
- Прозрачную работу с параметрами API
- Минимум зависимостей

## Новые возможности

### 1. Формат ответа (`--format`)
- `markdown` (по умолчанию) — к user-промпту добавляется инструкция "Format your response using Markdown."
- `json` — к user-промпту добавляется инструкция "Respond in JSON format."

Формат работает как дополнение к запросу пользователя, без использования system-роли. Ответ выводится как есть (без рендеринга).

### 2. Пользовательская инструкция формата (`--format-hint`)
- Позволяет указать любую кастомную инструкцию форматирования
- Если `--format-hint` задан, он **переопределяет** `--format`
- При одновременном использовании `--format-hint` и ненулевого `--format` выводится предупреждение

Примеры:
- `--format-hint "Format as a numbered list"` — запросить нумерованный список
- `--format-hint "Use bullet points and bullet points"` — запросить маркированный список
- `--format-hint "Present as a table with columns: Name, Description"` — запросить таблицу

### 3. Ограничение токенов (`--max-tokens`)
- `0` (по умолчанию) — без ограничений
- Любое положительное число — максимальное количество токенов в ответе
- Отправляет оба параметра: `max_tokens` и `max_completion_tokens`

### 3. Stop sequences (`--stop`)
- Можно указывать несколько раз
- Последовательности передаются в параметр `Stop` API-запроса
- LLM остановит генерацию при встрече любой из указанных последовательностей

### 4. Режим отладки (`--debug`)
- Выводит в `stderr` полный JSON payload запроса и статистику токенов ответа
- Показывает `finish_reason` — причину остановки генерации:
  - `stop` — модель завершила ответ самостоятельно (ограничение `max_tokens` не сработало)
  - `length` — генерация остановлена лимитом токенов (ограничение сработало)

## Ограничения `--max-tokens`

Не все модели и провайдеры одинаково поддерживают ограничение токенов:

| Провайдер / Модель | Поведение |
|---|---|
| OpenAI `gpt-4o`, `gpt-4o-mini` | Работает (`max_completion_tokens`) |
| OpenRouter обычные модели | Работает |
| OpenRouter reasoning-модели (`gpt-oss-*`) | **Может игнорироваться** — reasoning-токены не учитываются в `max_tokens` |
| OpenRouter free-tier (`:free`) | **Может игнорироваться** — free-провайдеры не всегда поддерживают ограничения |

> Используйте `--debug` чтобы проверить `finish_reason`: если он `stop` при малом `--max-tokens` — ограничение проигнорировано на стороне провайдера.

## Использование

```bash
# Markdown формат (по умолчанию)
./ai-adv-agent-day2 --query "Расскажи про Go"

# JSON формат
./ai-adv-agent-day2 --query "Список языков программирования" --format json

# Кастомная инструкция форматирования (переопределяет --format)
./ai-adv-agent-day2 --query "Достопримечательности Казани" --format-hint "Format as a numbered list"

# Ограничение токенов
./ai-adv-agent-day2 --query "Длинная история" --max-tokens 100

# Stop sequences
./ai-adv-agent-day2 --query "Список из 10 пунктов" --stop "5." --stop "6."

# Комбинирование параметров
./ai-adv-agent-day2 \
  --query "Структурированные данные" \
  --format json \
  --max-tokens 200 \
  --stop "END"

# Отладка — показать payload и usage
./ai-adv-agent-day2 --debug --max-tokens 50 --query "Краткий ответ"
```

## Переменные окружения

Те же, что и в Day1:
- `LLM_PROVIDER` — `openai` или `openrouter` (обязательно)
- `LLM_API_KEY` — API ключ (обязательно)
- `LLM_MODEL` — модель (опционально)
- `LLM_BASE_URL` — базовый URL API (опционально)

## Сборка

```bash
go build -o ai-adv-agent-day2 .
```
